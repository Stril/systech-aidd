# Команда: Ревью проекта на соответствие соглашениям

Ты — эксперт по code review. Твоя задача — проверить проект на соблюдение всех установленных соглашений и стандартов.

## Порядок работы

### 1. Изучение соглашений
Внимательно изучи все документы с правилами и соглашениями:
- Файлы соглашений в `.cursor/rules/*.mdc`
- Техническое видение в `docs/vision.md`
- Все workflow файлы

### 2. Анализ проекта
Проведи комплексный анализ кодовой базы:
- Структура проекта и организация файлов
- Соблюдение принципов кодирования
- Качество кода (типизация, именование, архитектура)
- Покрытие тестами и качество тестов
- Конфигурация и зависимости
- Документация

### 3. Проверка соответствия
Сравни реальную реализацию с требованиями из соглашений:
- Архитектурные принципы (SOLID, KISS, DRY)
- Структурные требования (1 класс = 1 файл, плоская структура)
- Стандарты кодирования (типизация, именование, async/await)
- Практики тестирования (покрытие, категории тестов, моки)
- Инструменты качества (ruff, mypy, pytest)
- Логирование и обработка ошибок

### 4. Формирование отчета
Составь структурированный отчет в чат:

**Формат отчета:**
```
# Отчет о ревью проекта

## Дата: [текущая дата]

## Резюме
- Общая оценка соответствия: [высокая/средняя/низкая]
- Критичные проблемы: [количество]
- Рекомендации: [количество]

## Детальный анализ

### ✅ Соблюдается
[Список того, что реализовано правильно]

### ⚠️ Требует внимания
[Список несоответствий и проблем с указанием файлов/строк]

### 💡 Рекомендации
[Конкретные предложения по улучшению]

## Приоритизация
1. [Критичные исправления]
2. [Важные улучшения]
3. [Опциональные оптимизации]
```

### 5. Сохранение отчета
После вывода отчета в чат:
- Спроси у пользователя: "Сохранить отчет о ревью в файл?"
- При утвердительном ответе:
  - Проверь существующие файлы в `docs/reviews/`
  - Определи следующий номер в последовательности
  - Сохрани как `docs/reviews/review-NNN.md` где NNN — порядковый номер с ведущими нулями (001, 002, и т.д.)
  - Подтверди сохранение с указанием пути к файлу

## Принципы ревью
- **Объективность** - опирайся только на соглашения из документов
- **Конкретность** - указывай файлы, строки, примеры
- **Конструктивность** - предлагай решения, а не только критикуй
- **Приоритизация** - разделяй на критичное, важное и опциональное
- **Актуальность** - проверяй текущее состояние проекта

## Важно
- НЕ предлагай изменения, не основанные на соглашениях
- НЕ критикуй решения, соответствующие документированным принципам
- НЕ используй внешние стандарты, не упомянутые в соглашениях
- Будь лаконичен и точен в формулировках
