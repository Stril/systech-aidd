# ADR-002: Использование OpenAI Client с OpenRouter для работы с LLM

## Статус
Принято

## Контекст
При разработке LLM-ассистента в виде Telegram-бота необходимо выбрать подход к интеграции с языковыми моделями. Проект требует:

- Работу с различными LLM моделями (GPT-4, Claude, Llama и др.)
- Унифицированный API для взаимодействия с моделями
- Соответствие принципам KISS и минимализма
- Быстрый старт разработки без изучения специфики каждого провайдера
- Экономическую эффективность использования LLM

## Проблема
Необходимо решить, как организовать взаимодействие с LLM, чтобы обеспечить:
- Единообразный интерфейс для различных моделей
- Простоту интеграции и поддержки
- Гибкость в выборе моделей
- Соответствие принципам проекта (KISS, минимум зависимостей)
- Экономическую эффективность

## Варианты решения

### Вариант 1: Прямая интеграция с каждым провайдером (отклонен)
```python
# Отдельные клиенты для каждого провайдера
class OpenAIClient:
    def send_message(self, messages): pass

class AnthropicClient:
    def send_message(self, messages): pass

class LlamaClient:
    def send_message(self, messages): pass
```

**Плюсы:**
- Прямой контроль над каждым API
- Оптимизация под специфику провайдера

**Минусы:**
- Множество зависимостей
- Разные API для каждой модели
- Сложность поддержки и тестирования
- Нарушение принципа KISS

### Вариант 2: Собственная абстракция (отклонен)
```python
class LLMClient:
    def __init__(self, provider: str, api_key: str):
        if provider == "openai":
            self.client = OpenAIClient(api_key)
        elif provider == "anthropic":
            self.client = AnthropicClient(api_key)
        # ...
```

**Плюсы:**
- Единый интерфейс
- Контроль над реализацией

**Минусы:**
- Дополнительная сложность
- Необходимость поддержки всех провайдеров
- Оверинжиниринг для MVP
- Нарушение принципа "минимум зависимостей"

### Вариант 3: OpenAI Client с OpenRouter (принят)
```python
class OpenAIClient:
    def __init__(self, api_key: str, base_url: str, model: str):
        self.client = openai.OpenAI(
            api_key=api_key,
            base_url=base_url  # https://openrouter.ai/api/v1
        )
        self.model = model
    
    def send_message(self, messages: List[Message], system_prompt: str) -> str:
        response = self.client.chat.completions.create(
            model=self.model,
            messages=[{"role": "system", "content": system_prompt}] + messages
        )
        return response.choices[0].message.content
```

**Плюсы:**
- Единый API для всех моделей
- Минимум зависимостей (только `openai`)
- Простота интеграции
- Экономическая эффективность
- Автоматический доступ к новым моделям
- Соответствие принципам проекта

**Минусы:**
- Зависимость от OpenRouter как промежуточного слоя
- Потенциальные ограничения по сравнению с прямым API

## Решение
Принят **Вариант 3: OpenAI Client с OpenRouter**.

### Обоснование

#### 1. Соответствие принципам проекта
- **KISS (Keep It Simple, Stupid)**: Один клиент для всех моделей
- **Минимум зависимостей**: Только пакет `openai`
- **Быстрый старт**: Стандартный API без изучения специфики
- **Explicit is better than implicit**: Явная конфигурация модели и провайдера

#### 2. Технические преимущества
- **Унифицированный API**: Единообразный интерфейс для GPT-4, Claude, Llama
- **Стандартизация**: Сообщения в формате `[{"role": "user", "content": "..."}]`
- **Надежность**: Единая обработка ошибок и исключений
- **Производительность**: Кэширование и load balancing через OpenRouter

#### 3. Экономические преимущества
- **Сравнение цен**: Выбор наиболее выгодной модели для задачи
- **Прозрачность**: Четкое понимание стоимости каждого запроса
- **Оптимизация**: Использование дешевых моделей для простых задач

#### 4. Гибкость и расширяемость
- **Переключение моделей**: Через конфигурацию без изменения кода
- **Новые модели**: Автоматический доступ через OpenRouter
- **A/B тестирование**: Простое сравнение разных моделей
- **Fallback**: Переключение на другую модель при недоступности

#### 5. Соответствие архитектуре проекта
```python
# Интеграция с существующей архитектурой
class OpenAIClient:
    def __init__(self, api_key: str, base_url: str, model: str)
    def send_message(self, messages: List[Message], system_prompt: str) -> str
    def validate_response(self, response: str) -> bool
```

#### 6. Принципы SOLID
- **Single Responsibility**: Класс отвечает только за взаимодействие с LLM
- **Dependency Inversion**: Зависимость от абстракции (OpenAI API)
- **Open/Closed**: Легко расширяется новыми моделями без изменения кода

### Положительные
- ✅ Единый API для всех LLM моделей
- ✅ Минимум зависимостей (только `openai`)
- ✅ Простота интеграции и поддержки
- ✅ Экономическая эффективность
- ✅ Автоматический доступ к новым моделям
- ✅ Соответствие принципам KISS и минимализма
- ✅ Легкое тестирование с mock-объектами
- ✅ Простое переключение между моделями

### Отрицательные
- ⚠️ Зависимость от OpenRouter как промежуточного слоя
- ⚠️ Потенциальные ограничения по сравнению с прямым API
- ⚠️ Дополнительная точка отказа (OpenRouter)

### Нейтральные
- 📝 Конфигурация через переменные окружения

## Реализация

### Конфигурация
```python

OPENAI_MODEL=openai/gpt-4  # или anthropic/claude-3, meta-llama/llama-2
```

```python
        base_url=settings.OPENAI_BASE_URL,
        model=settings.OPENAI_MODEL
    )
    # ... остальная инициализация
```

### Пример использования
```python
# Переключение моделей через конфигурацию
```

### Тестирование

## Альтернативы, которые были рассмотрены
- **Прямая интеграция с каждым провайдером** - отклонена как нарушающая принцип KISS
- **Собственная абстракция** - отклонена как оверинжиниринг для MVP
- **HTTP клиент с прямыми запросами** - отклонена как избыточная сложность
- **Асинхронные клиенты** - отклонены как преждевременная оптимизация
