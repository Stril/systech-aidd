# ADR-004: Использование Ruff + Mypy для контроля качества кода

## Статус
Предлагается к принятию

## Контекст
При разработке LLM-ассистента в виде Telegram-бота необходимо обеспечить высокое качество кода и его надежность. Проект требует:

- Единообразного стиля кода
- Раннего обнаружения ошибок типизации
- Быстрой проверки кода в CI/CD
- Минимальной конфигурации инструментов
- Соответствия принципам KISS и минимализма

## Проблема
Необходимо выбрать инструменты для:
- Линтинга и форматирования кода
- Статической проверки типов
- Автоматического обнаружения потенциальных ошибок
- Поддержания единообразного стиля кода в команде

## Варианты решения

### Вариант 1: Классический стек (Black + Flake8 + isort + Mypy) (отклонен)
```toml
[tool.black]
line-length = 88

[tool.flake8]
max-line-length = 88

[tool.isort]
profile = "black"
```

**Плюсы:**
- Проверенное решение
- Большое сообщество

**Минусы:**
- Множество зависимостей
- Медленная работа на больших проектах
- Сложная конфигурация
- Необходимость запускать несколько инструментов

### Вариант 2: Ruff + Mypy (принят)
```toml
[tool.ruff]
line-length = 88
target-version = "py311"

[tool.mypy]
python_version = "3.11"
strict = true
```

**Плюсы:**
- Ruff заменяет Black, Flake8, isort одним инструментом
- В 10-100 раз быстрее традиционных инструментов
- Минимальная конфигурация
- Mypy - стандарт де-факто для проверки типов
- Автоматическое исправление проблем

**Минусы:**
- Ruff относительно новый инструмент (стабильный с 2023)

## Решение
Принят **Вариант 2: Ruff + Mypy**.

### Обоснование

#### 1. Ruff - универсальный линтер и форматтер
- **Скорость**: Написан на Rust, работает в 10-100 раз быстрее аналогов
- **Всё-в-одном**: Заменяет Black, Flake8, isort, pyupgrade и др.
- **Автофикс**: Автоматически исправляет большинство проблем
- **Минимализм**: Одна зависимость вместо пяти

#### 2. Mypy - статический анализатор типов
- **Стандарт индустрии**: Де-факто стандарт для Python
- **Type safety**: Проверка корректности type hints
- **Раннее обнаружение ошибок**: До выполнения кода
- **IDE интеграция**: Поддержка во всех современных IDE

#### 3. Соответствие принципам проекта
- **KISS**: Минимальная конфигурация
- **Минимум зависимостей**: 2 инструмента вместо 5+
- **Explicit is better than implicit**: Type hints делают код понятнее
- **Производительность**: Быстрая проверка в CI/CD

## Последствия

### Положительные
- ✅ Единообразный стиль кода
- ✅ Раннее обнаружение ошибок типизации
- ✅ Быстрая проверка (секунды вместо минут)
- ✅ Автоматическое исправление проблем
- ✅ Минимальная конфигурация
- ✅ Улучшение читаемости кода через type hints
- ✅ Поддержка IDE (автодополнение, refactoring)

### Отрицательные
- ⚠️ Необходимость добавлять type hints ко всем функциям
- ⚠️ Начальная настройка strictness mypy

### Нейтральные
- 📝 Pre-commit hooks для автопроверки
- 📝 CI/CD интеграция обязательна
- 📝 Постепенное внедрение строгой типизации

## Реализация

### Установка
```bash
uv add --dev ruff mypy
```

### Конфигурация в pyproject.toml
```toml
[tool.ruff]
line-length = 88
target-version = "py311"
select = ["E", "F", "I", "UP"]  # pycodestyle, pyflakes, isort, pyupgrade
fix = true

[tool.mypy]
python_version = "3.11"
warn_return_any = true
warn_unused_configs = true
disallow_untyped_defs = true
```

### Makefile команды
```makefile
format:
	ruff format .
	ruff check --fix .

lint:
	ruff check .
	mypy src/

check: lint test
```

### Pre-commit hook
```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
```

## Альтернативы, которые были рассмотрены
- **Black + Flake8 + isort** - отклонено из-за множества зависимостей
- **Pylint** - отклонено из-за медленной работы
- **Только Ruff без Mypy** - отклонено, т.к. нужна проверка типов
- **Pyright вместо Mypy** - отклонено, Mypy более популярен в Python community
