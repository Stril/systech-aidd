# ADR-007: Выбор SQLAlchemy + Alembic для работы с SQLite

## Статус
Принято

## Контекст
В рамках спринта SP-1 необходимо реализовать персистентное хранение данных с использованием SQLite (согласно ADR-006). Требуется выбрать инструменты для работы с БД и управления миграциями.

Требования:
- Async поддержка (проект использует async/await архитектуру)
- Управление схемой БД (миграции)
- Простота использования (принцип KISS)
- Минимум зависимостей
- Типобезопасность

## Варианты решения

### Вариант 1: Raw SQL + aiosqlite (отклонен)
Прямая работа с SQL через aiosqlite без ORM и системы миграций.

**Плюсы:**
- Минимум зависимостей (только aiosqlite)
- Полный контроль над SQL
- Максимальная производительность

**Минусы:**
- ❌ Ручное управление миграциями (скрипты SQL)
- ❌ Нет типобезопасности
- ❌ Много boilerplate кода
- ❌ Сложнее поддерживать при изменении схемы
- ❌ Нет автоматической генерации миграций
- ❌ Ручная конвертация DB ↔ Domain моделей

### Вариант 2: SQLAlchemy + Alembic (принят)
Стандартный ORM для Python с системой миграций Alembic.

**Плюсы:**
- ✅ Стандарт индустрии для Python
- ✅ Отличная async поддержка (SQLAlchemy 2.0+)
- ✅ Автоматическая генерация миграций
- ✅ Типобезопасность через `Mapped[]`
- ✅ Версионирование схемы БД
- ✅ Декларативное описание моделей
- ✅ Богатая экосистема и документация
- ✅ Удобный query builder
- ✅ Поддержка разных БД (легкая миграция на PostgreSQL)

**Минусы:**
- ⚠️ Две дополнительные зависимости
- ⚠️ Небольшой overhead по сравнению с raw SQL

### Вариант 3: Tortoise ORM (отклонен)
Async-native ORM для Python.

**Плюсы:**
- Async-first дизайн
- Простой API

**Минусы:**
- ❌ Меньшая зрелость по сравнению с SQLAlchemy
- ❌ Меньше материалов и community support
- ❌ Менее стандартный выбор
- ❌ Система миграций (Aerich) менее развита

## Решение
Принят **Вариант 2: SQLAlchemy + Alembic**.

### Обоснование

#### 1. Стандарт индустрии
SQLAlchemy - де-факто стандарт ORM в Python экосистеме. Это означает:
- Огромное community и поддержка
- Обширная документация и примеры
- Проверенная годами стабильность
- Легко найти специалистов, знакомых с инструментом

#### 2. Современная async поддержка
SQLAlchemy 2.0+ предоставляет полноценную async поддержку:
```python
async with async_session_maker() as session:
    result = await session.execute(select(User).where(User.user_id == 123))
    user = result.scalar_one_or_none()
```

#### 3. Автоматические миграции через Alembic
Alembic - стандартный инструмент миграций для SQLAlchemy:
```bash
# Создание миграции
alembic revision --autogenerate -m "Add new column"

# Применение миграций
alembic upgrade head
```

Миграции создаются автоматически на основе изменений моделей.

#### 4. Типобезопасность
SQLAlchemy 2.0+ с `Mapped[]` типами обеспечивает полную типобезопасность:
```python
class UserDB(Base):
    user_id: Mapped[int] = mapped_column(primary_key=True)
    username: Mapped[str | None] = mapped_column(nullable=True)
```

Mypy проверяет типы на этапе разработки.

#### 5. Простота миграции на другую БД
Если в будущем понадобится PostgreSQL или MySQL, достаточно:
- Изменить `DATABASE_URL` в настройках
- Запустить миграции
- Код остается без изменений

#### 6. Декларативное описание
Модели описываются декларативно, что улучшает читаемость:
```python
class MessageDB(Base):
    __tablename__ = "messages"

    id: Mapped[int] = mapped_column(primary_key=True)
    content: Mapped[str] = mapped_column(Text)
    deleted_at: Mapped[datetime | None] = mapped_column(nullable=True)

    __table_args__ = (
        Index("idx_messages_deleted_at", "deleted_at"),
    )
```

## Последствия

### Положительные
- ✅ Стандартное решение, известное Python сообществу
- ✅ Автоматическая генерация и управление миграциями
- ✅ Типобезопасный код с проверкой mypy
- ✅ Легкая поддержка и расширение схемы БД
- ✅ Отличная async поддержка
- ✅ Возможность миграции на другую БД без изменения кода
- ✅ Богатая документация и примеры

### Отрицательные
- ⚠️ Две дополнительные зависимости (sqlalchemy, alembic)
- ⚠️ Небольшой overhead по сравнению с raw SQL (не критично для нашего случая)

### Нейтральные
- 📝 Нужно изучить основы SQLAlchemy 2.0 и Alembic
- 📝 Миграции хранятся в отдельной директории `migrations/`
- 📝 Требуется настройка Alembic (единоразово)

## Реализация

### Зависимости
```toml
[dependencies]
sqlalchemy = {version = ">=2.0.0", extras = ["asyncio"]}
aiosqlite = ">=0.19.0"
alembic = ">=1.12.0"
```

### Структура проекта
```
src/
  database_models.py  # SQLAlchemy модели
  sqlite_storage.py   # Реализация storage
migrations/
  versions/           # Файлы миграций
  env.py             # Alembic окружение
alembic.ini          # Конфигурация Alembic
```

### Пример использования
```python
# Создание storage
storage = SQLiteStorage("sqlite+aiosqlite:///data/bot.db")

# Работа с данными
await storage.add_user(user)
user = await storage.get_user(user_id)
await storage.add_message_to_conversation(user_id, message)

# Graceful shutdown
await storage.close()
```

### Миграции
```bash
# Создать миграцию
alembic revision --autogenerate -m "Description"

# Применить миграции
alembic upgrade head

# Откатить миграцию
alembic downgrade -1
```
