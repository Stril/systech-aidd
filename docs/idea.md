# LLM-ассистент в виде Telegram-бота

## Описание проекта

LLM-ассистент представляет собой полноценный ИИ-продукт в виде Telegram-бота с четко определенной ролью. Это не универсальный помощник, а специализированный ассистент, выполняющий конкретную функцию в соответствии с заданным системным промптом. Роль ассистента определяется системным промптом, который хранится в конфигурационном файле и может быть легко изменена без изменения кода.

## Основные функции

### 1. Диалоговая система
- Ведение непрерывного диалога с пользователем
- Сохранение контекста разговора
- Обработка многоуровневых вопросов и ответов

### 2. Ролевая модель
- Использование системного промпта для определения конкретной роли ассистента
- Системный промпт хранится в отдельном конфигурационном файле
- Команда `/role` для отображения текущей роли ассистента
- Возможность настройки поведения и стиля общения через изменение файла промпта
- Адаптация ответов под заданную роль

### 3. Интеграция с LLM
- Подключение к языковой модели (например, GPT, Claude, или локальной модели)
- Обработка запросов пользователя через API
- Форматирование и отправка ответов

## Технические требования

### Архитектура
- **Frontend**: Telegram Bot API
- **Backend**: Python/Node.js сервер
- **LLM Integration**: API подключение к выбранной языковой модели
- **Database**: Хранение истории диалогов и пользовательских данных

### Основные компоненты
1. **Telegram Bot Handler** - обработка входящих сообщений
2. **LLM Client** - взаимодействие с языковой моделью
3. **Context Manager** - управление контекстом диалога
4. **Role Manager** - управление ролевыми настройками и загрузка системного промпта из файла
5. **System Prompt Storage** - хранение и загрузка системного промпта из конфигурационного файла
6. **Database Layer** - работа с данными

## Роль ассистента

Ассистент имеет четко определенную роль, которая задается через системный промпт в конфигурационном файле. Роль определяет специализацию и поведение ассистента.

### Принципы ролевой модели
- **Конкретность**: Роль должна быть четко определена и специализирована
- **Консистентность**: Ассистент последовательно выполняет свою функцию в рамках заданной роли
- **Прозрачность**: Пользователи могут узнать роль ассистента через команду `/role`
- **Гибкость**: Роль может быть изменена через редактирование файла системного промпта

### Примеры возможных ролей
- **Технический консультант** - помощь с программированием и IT
- **Образовательный ассистент** - помощь в обучении по конкретному предмету
- **Креативный помощник** - генерация контента и идей в определенной области
- **Аналитик** - анализ данных и информации в конкретной сфере
- **Специализированный эксперт** - экспертиза в узкой предметной области

## Технологический стек

- **Язык программирования**: Python 3.11+
- **Telegram Bot**: python-telegram-bot или aiogram
- **LLM API**: OpenAI GPT, Anthropic Claude, или локальные модели
- **База данных**: SQLite/PostgreSQL
- **Тестирование**: pytest для unit-тестов
- **Развертывание**: Docker, cloud hosting

## Тестирование

Проект должен включать простые unit-тесты для проверки основных компонентов системы. Тесты организуются с использованием фреймворка **pytest** и запускаются стандартной командой `pytest`.

## Конфигурация системного промпта

### Структура хранения
- Системный промпт хранится в отдельном файле (например, `system_prompt.txt` или `role_config.yaml`)
- Файл загружается при инициализации бота
- Изменение роли не требует перезапуска кода - достаточно обновить файл и перезапустить бот

### Формат промпта
Системный промпт должен содержать:
- Четкое описание роли ассистента
- Инструкции по стилю общения
- Границы компетенции
- Особые указания по обработке запросов

## Заключение

Данный проект представляет собой современное решение для создания специализированного ИИ-продукта в популярном мессенджере Telegram. Основной акцент делается на четкой специализации через ролевую модель, хранение системного промпта в конфигурационных файлах и качественном выполнении конкретной функции через LLM-технологии. Прозрачность роли обеспечивается командой `/role`, что позволяет пользователям понимать возможности и ограничения ассистента.
