# 📋 Шаблон дорожной карты итераций

> **Документ для кодового агента:** Используй этот шаблон для создания и обновления дорожной карты проекта.

---

## 🎯 Назначение шаблона

Этот шаблон предназначен для:
- Создания новых дорожных карт проекта
- Планирования итераций (спринтов) развития
- Документирования прогресса выполнения
- Обеспечения прозрачности и отслеживаемости изменений

---

## 📐 Принципы планирования

### 1. Уровень детализации
- **Высокоуровневый план** - описываем ЧТО делаем, НЕ описываем КАК
- **Цели спринта** - бизнес-задачи и пользовательская ценность
- **Состав работ** - основные направления, НЕ детальные задачи реализации
- **БЕЗ технических деталей** - не включаем классы, методы, алгоритмы

### 2. Структура спринтов
- **Код спринта:** SP-N (где N - порядковый номер)
- **Название:** Краткое, отражающее суть (3-5 слов)
- **Статус:** Одно из значений легенды статусов
- **Цель:** Ясная бизнес-цель в 1-2 предложениях
- **Состав работ:** Маркированный список направлений (3-10 пунктов)

### 3. Формат описания
- **Цель** - зачем этот спринт, какая проблема решается
- **Ключевые задачи** - что делается (направления работ)
- **Реализованные возможности** - что получит пользователь
- **Достигнутые результаты** - метрики, показатели качества
- **Технический стек** - основные технологии (при необходимости)
- **Ограничения соблюдены** - соответствие требованиям проекта

### 4. Что НЕ включать
❌ Детальные технические решения (классы, методы)
❌ Пошаговые инструкции реализации
❌ Обсуждение альтернатив (это для ADR)
❌ Конкретные значения параметров
❌ Тестовые сценарии

## 📊 Примеры описания спринтов

### Пример 1: MVP спринт

```markdown
### SP-0: MVP и Foundation (✅ Завершено)

**Период выполнения:** 10.10.2025 - 16.10.2025

**Цель:**
Создать полноценный MVP LLM Telegram-бота со специализированной ролевой моделью, качественной архитектурой и высоким покрытием тестами.

**Ключевые задачи:**
1. ✅ **MVP разработка** - Базовая функциональность бота
2. ✅ **Интеграция LLM** - Подключение к внешнему API
3. ✅ **Качество кода** - Настройка линтеров и автоматизации
4. ✅ **Тестирование** - Покрытие тестами основного функционала

**Реализованные возможности:**
- ✅ Полнофункциональный Telegram-бот с командами
- ✅ Интеграция с LLM через OpenRouter
- ✅ Управление контекстом диалога
- ✅ Структурированное логирование

**Достигнутые результаты:**
- ✅ Высокое покрытие тестами: 121 тест, 98% coverage
- ✅ Автоматизация качества: ruff + mypy
- ✅ Полная документация и guides
- ✅ Готов к продуктивному использованию
```

## 🔄 Обновление roadmap

### При создании нового спринта:
1. Добавь строку в таблицу спринтов
2. Создай секцию с описанием спринта
3. Укажи статус `📋 Планируется`
4. Определи цель и состав работ (высокий уровень)

### При начале работы над спринтом:
1. Измени статус на `🔄 В работе`
2. Добавь период выполнения (дата начала)
3. Детализируй ключевые задачи (если требуется)
4. Создай план/тасклист (если требуется)

### При завершении спринта:
1. Измени статус на `✅ Завершено`
2. Добавь дату завершения
3. Заполни разделы "Реализованные возможности"
4. Заполни "Достигнутые результаты" с метриками
5. Добавь "Ограничения соблюдены"
6. Отметь все ключевые задачи как ✅

### При отмене/приостановке:
1. Измени статус на `❌ Отменено` или `⏸️ Приостановлено`
2. Добавь примечание с причиной

## 📚 Связанные документы

Roadmap связан с другими типами документов:

- **ADR** (Architecture Decision Records) - технические решения и архитектура
- **Tasklists** - детальные списки задач для спринтов
- **Plans** - рабочие планы выполнения спринтов
- **Vision** - общее техническое видение проекта
- **Idea** - концепция и описание продукта

**Разделение ответственности:**
- Roadmap - ЧТО делаем и ЗАЧЕМ (бизнес-уровень)
- Plans/Tasklists - КАК делаем (тактический уровень)
- ADR - ПОЧЕМУ так сделали (технические решения)

---

## 💡 Советы по использованию

1. **Держи roadmap актуальным** - обновляй статусы регулярно
2. **Фокус на ценности** - всегда указывай, что получает пользователь
3. **Высокий уровень** - roadmap читают не только разработчики
4. **Метрики важны** - указывай конкретные результаты (coverage, тесты, сроки)
5. **Связность документов** - ссылайся на ADR, планы, тасклисты
6. **История изменений** - не удаляй завершенные спринты, они показывают прогресс
7. **Реалистичность** - лучше меньше спринтов, но завершенных качественно

---

**Помни:** Roadmap - это инструмент коммуникации и планирования, а не технический дизайн-документ.
