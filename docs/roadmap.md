## Описание спринтов

### SP-0: MVP и Foundation (✅ Завершено)

**Период выполнения:** 10.10.2025 - 16.10.2025

**Цель:**
Создать полноценный MVP LLM Telegram-бота со специализированной ролевой моделью, качественной архитектурой и высоким покрытием тестами.

**Ключевые достижения:**
- ✅ Полнофункциональный Telegram-бот с командами `/start`, `/help`, `/role`, `/reset`
- ✅ Интеграция с LLM через OpenRouter (поддержка различных моделей)
- ✅ Ролевая модель - системный промпт из файла, команда `/role`
- ✅ Управление контекстом (последние 10 сообщений)
- ✅ In-memory хранилище для пользователей и диалогов
- ✅ Структурированное логирование (файлы по дням, формат с разделителем `|`)
- ✅ Автоматизация качества: ruff (линтер/форматтер), mypy (strict mode)
- ✅ Чистая архитектура: 1 класс = 1 файл, SOLID, DRY
- ✅ Async/await архитектура с run_in_executor для OpenAI
- ✅ Высокое покрытие тестами: 121 тест, 98.12% coverage
- ✅ Unit, integration и property-based тесты (hypothesis)
- ✅ Примеры ролей для различных специализаций
- ✅ Полная документация и guides

**Технологический стек:**
- Python 3.11+, uv для зависимостей
- aiogram (Telegram Bot API)
- openai client + OpenRouter
- structlog (логирование)
- pytest + hypothesis (тестирование)
- ruff + mypy (качество кода)

**Итоги:**
Проект готов к продуктивному использованию. Создана прочная основа для дальнейшего развития с фокусом на качество кода, тестируемость и простоту архитектуры.

### SP-1: Персистентное хранение данных (📋 Планируется)

**Цель:**
Реализовать сохранение истории диалогов в базе данных вместо текущего in-memory хранения. История диалогов должна сохраняться между перезапусками бота.

**Ключевые задачи:**
1. **Анализ требований** - Изучить текущую модель данных и операции над ней
2. **Выбор технологий** - Определить СУБД и инструмент миграций, оформить через ADR ✅
   - [ADR-006: Выбор SQLite](adrs/adr-006-sqlite-database-choice.md)
   - [ADR-007: SQLAlchemy ORM + Alembic](adrs/adr-007-sqlalchemy-alembic.md)
3. **Docker окружение** - Настроить Docker support
4. **Проектирование схемы** - Создать таблицы, связи, индексы, ER-диаграммы
5. **Система миграций** - Внедрить управление версиями схемы БД
6. **Data Access Layer** - Разработать слой доступа к данным с async поддержкой
7. **Рефакторинг** - Заменить MemoryStorage на database storage

**Ожидаемые результаты:**
- История диалогов сохраняется между перезапусками
- Документированное архитектурное решение (ADR)
- Миграции для версионирования схемы
- Тесты для слоя работы с БД
- Docker Compose для локальной разработки

**Ограничения:**
- Сохраняется принцип "1 класс = 1 файл"
- Поддержка async/await
- Coverage >= 80%
