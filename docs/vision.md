# Техническое видение проекта LLM-ассистента

## 1. Технологии

### Обязательные технологии:
- **Python 3.11+** - основной язык разработки
- **uv** - управление зависимостями и виртуальными окружениями
- **openai client** - для работы с LLM через провайдер Openrouter
- **aiogram** - для интеграции с Telegram Bot API (метод polling)
- **make** - для сборки и автоматизации проекта

### Дополнительные технологии:
- **pydantic** - валидация данных и конфигурации
- **python-dotenv** - управление переменными окружения
- **structlog** - структурированное логирование
- **pytest** - unit-тестирование
- **ruff** - линтер и форматтер кода
- **mypy** - статическая типизация
- **hypothesis** - property-based тестирование

### Принципы выбора:
- Максимальная простота
- Минимум зависимостей
- Быстрый старт разработки
- Хранение данных в памяти (без БД на данном этапе)
- Запуск через make

## 2. Принцип разработки

### Основные принципы:
- **KISS (Keep It Simple, Stupid)** - максимальная простота во всем
- **ООП с принципом "1 класс = 1 файл"** - строгое соблюдение
- **Никакого оверинжиниринга** - только необходимый функционал
- **Быстрая проверка идеи** - MVP подход

### Принципы кодирования:
- **Single Responsibility** - каждый класс отвечает за одну задачу
- **Dependency Injection** - простая инъекция зависимостей
- **Fail Fast** - быстрое обнаружение ошибок
- **Explicit is better than implicit** - явность лучше неявности

### Структурные принципы:
- Минимальное количество файлов
- Понятные имена классов и методов
- Простая конфигурация
- Обработка ошибок через логирование в файл

## 4. Архитектура проекта

### Компоненты системы:
1. **TelegramBot** - основной класс бота, инициализация и запуск
2. **MessageHandler** - координация обработки сообщений
3. **MessageExtractor** - извлечение данных из Telegram сообщений
4. **BotMessages** - константы текстовых сообщений бота
5. **OpenAIClient** - асинхронное взаимодействие с LLM через Openrouter
6. **ContextManager** - управление контекстом диалога в памяти
7. **MemoryStorage** - хранение данных пользователей и диалогов в памяти
8. **Settings** - конфигурация приложения (включая загрузку системного промпта из файла)

### Поток данных:
```
1. Получение сообщения:
   Telegram API → TelegramBot → MessageHandler

2. Извлечение данных:
   MessageHandler → MessageExtractor → MessageContext

3. Обработка запроса:
   MessageHandler → ContextManager (получает историю)
   ContextManager → MemoryStorage (читает историю)
   MessageHandler → OpenAIClient (async) → Openrouter LLM

4. Сохранение и отправка:
   LLM Response → ContextManager (обновляет контекст)
   ContextManager → MemoryStorage (пишет историю)
   MessageHandler → TelegramBot → Telegram API
```

### Принципы архитектуры:
- **Простая линейная архитектура** - без сложных паттернов
- **SOLID принципы** - Single Responsibility, Dependency Injection
- **DRY** - избегание дублирования кода через вспомогательные классы
- **Слабая связанность** - классы взаимодействуют через DI
- **Единственная ответственность** - каждый класс решает одну задачу
- **Async/await** - правильное использование асинхронности
- **In-memory storage** - все данные в оперативной памяти
- **Валидация в классах** - проверки данных внутри каждого класса
- **Обработка ошибок в каждом классе** - локальная обработка исключений

## 5. Модель данных

### Основные классы:

#### User (Пользователь):
```python
class User:
    user_id: int              # Telegram user ID
    username: str             # Telegram username (опционально)
    first_name: str           # Имя пользователя
    created_at: datetime      # Время регистрации
    last_activity: datetime   # Последняя активность
```

#### Message (Сообщение):
```python
class Message:
    role: str                 # "user" или "assistant"
    content: str              # Текст сообщения
    timestamp: datetime       # Время сообщения
```

#### Conversation (Диалог):
```python
class Conversation:
    chat_id: int              # ID чата (Telegram chat ID)
    user_id: int              # ID пользователя
    messages: List[Message]   # История сообщений
    context: str              # Системный промпт/роль
    created_at: datetime      # Время создания диалога
    updated_at: datetime      # Время последнего обновления
```

### Структура хранения в памяти:
```python
# MemoryStorage будет содержать:
class MemoryStorage:
    users: Dict[int, User]                    # Словарь пользователей
    conversations: Dict[int, Conversation]    # Словарь диалогов по chat_id
```

### Принципы модели данных:
- **Простые классы** - без сложной иерархии
- **Типизация** - использование type hints
- **Минимальные поля** - только необходимые данные
- **Разделение по chat_id** - каждый чат отдельный диалог

## 6. Работа с LLM

### Интеграция с Openrouter:
- **Провайдер**: Openrouter для доступа к различным LLM
- **Клиент**: OpenAI client для унифицированного API
- **Модели**: Настраиваемые через конфигурацию (GPT-4, Claude, etc.)

### Основные функции OpenAIClient:
```python
class OpenAIClient:
    def __init__(self, api_key: str, base_url: str, model: str)
    async def send_message(self, messages: List[Message], system_prompt: str) -> str
    def _sync_send_message(self, messages: List[Message], system_prompt: str) -> str
```

**Важно**: OpenAIClient использует async/await с run_in_executor для неблокирующих вызовов

### Обработка контекста:
- **ContextManager** управляет историей диалога
- Ограничение количества сообщений в контексте (последние 10 сообщений)
- Системный промпт для определения роли ассистента
- Обработка ошибок API и таймаутов

### Принципы работы с LLM:
- **Простой API** - минимум абстракций
- **Обработка ошибок** - graceful degradation
- **Валидация ответов** - проверка корректности
- **Логирование запросов** - для отладки
- **Без retry логики** - простая обработка ошибок

## 7. Сценарии работы

### Сценарий 1: Первый запуск
1. Пользователь отправляет `/start`
2. Бот создает нового пользователя в MemoryStorage
3. Бот приветствует пользователя и объясняет возможности
4. Роль ассистента загружается из файла system_prompt.txt

### Сценарий 2: Обычный диалог
1. Пользователь отправляет текстовое сообщение
2. MessageHandler получает сообщение
3. ContextManager добавляет сообщение в историю диалога
4. OpenAIClient отправляет запрос к LLM
5. Бот отправляет ответ пользователю
6. Контекст обновляется в MemoryStorage

### Сценарий 3: Справка
1. Пользователь отправляет команду `/help`
2. MessageHandler обрабатывает команду
3. Бот отправляет справку с доступными командами и возможностями

### Сценарий 4: Просмотр роли
1. Пользователь отправляет команду `/role`
2. MessageHandler обрабатывает команду
3. Бот отображает текущую роль ассистента из системного промпта

### Сценарий 5: Обработка ошибок
1. Ошибка API LLM → логирование + сообщение пользователю
2. Неверный формат сообщения → валидация + уведомление
3. Превышение лимита контекста → обрезка истории

### Системный промпт:
Системный промпт хранится в отдельном конфигурационном файле и загружается при инициализации. Это позволяет легко изменять роль ассистента без изменения кода.

**Дефолтный промпт**:
```
"Ты - универсальный помощник, готовый помочь с различными вопросами.
Отвечай дружелюбно, информативно и по существу.
Если не знаешь ответа, честно скажи об этом."
```

## 8. Подход к конфигурированию

### Конфигурация через переменные окружения:
- **Файл `.env`** - для локальной разработки
- **Файл `.env.example`** - шаблон конфигурации
- **Класс Settings** - валидация и загрузка настроек

### Основные параметры конфигурации:
```python
class Settings:
    # Telegram Bot
    TELEGRAM_BOT_TOKEN: str

    # Openrouter/LLM
    OPENAI_API_KEY: str
    OPENAI_BASE_URL: str = "https://openrouter.ai/api/v1"
    OPENAI_MODEL: str = "openai/gpt-4"

    # Системный промпт
    SYSTEM_PROMPT_FILE: str = "system_prompt.txt"

    # Логирование
    LOG_LEVEL: str = "INFO"
    LOG_FILE_PATH: str = "logs/"

    # Контекст
    MAX_CONTEXT_MESSAGES: int = 10
```

### Принципы конфигурации:
- **Простота** - минимум параметров
- **Валидация** - проверка обязательных полей
- **Значения по умолчанию** - для необязательных параметров
- **Безопасность** - секреты только в .env

### Конфигурация системного промпта:
- **Файл промпта** - хранится в `system_prompt.txt` (или другом файле по конфигурации)
- **Загрузка** - выполняется при инициализации Settings
- **Изменение роли** - редактирование файла + перезапуск бота
- **Формат** - простой текстовый файл с описанием роли и инструкциями

## 9. Подход к логированию

### Структурированное логирование:
- **Библиотека**: structlog для структурированных логов
- **Формат**: Текстовый файл с разделителем "|" (вертикальная черта)
- **Файлы**: Отдельные файлы по дням (YYYY-MM-DD.log)
- **Уровни**: DEBUG, INFO, WARNING, ERROR (все по потребности)

### Основные события для логирования:
```python
# Пользовательские действия
logger.info("user_message|user_id=123|chat_id=456|message=Hello")

# LLM запросы
logger.info("llm_request|model=gpt-4|messages_count=5")
logger.info("llm_response|response_length=150|response_time=2.3")

# Ошибки
logger.error("llm_error|error=API timeout|user_id=123")
logger.error("telegram_error|error=Invalid token")
```

### Принципы логирования:
- **Текстовый формат** - разделитель "|" для парсинга
- **Контекст** - user_id, chat_id, timestamp
- **Безопасность** - не логируем секретные данные
- **Производительность** - асинхронное логирование
- **Гибкость уровней** - все уровни по потребности
