## Описание спринтов

### FE-SP-1: Требования к дашборду и Mock API (✅ Завершено)

**Цель:**
Сформировать четкие требования к пользовательскому интерфейсу дашборда статистики и создать Mock API, чтобы frontend разработка могла вестись независимо от backend реализации. API должен предоставлять статистику по диалогам на основе существующих данных в базе.

**Ключевые задачи:**
1. ✅ **Функциональные требования к дашборду** - Анализ существующих данных и формирование емких требований к UI без доработок backend
2. ✅ **API контракт** - Проектирование простого REST API (KISS - один endpoint для статистики)
3. ✅ **Интерфейс StatCollector** - Проектирование абстракции с потенциальными реализациями Mock и Real
4. ✅ **Mock реализация** - Разработка Mock StatCollector с жестко заданными тестовыми данными
5. ✅ **API entrypoint** - Создание точки входа для запуска API сервера (FastAPI)
6. ✅ **Документация** - Автоматическая генерация API документации (OpenAPI/Swagger)
7. ✅ **Команды запуска** - Создание Makefile команд для запуска API и тестирования

**Ожидаемые результаты:**
- ✅ Документ с функциональными требованиями к дашборду (api/README.md)
- ✅ Спецификация API контракта (Pydantic модели)
- ✅ Работающий Mock API с тестовыми данными
- ✅ Автоматически сгенерированная API документация (OpenAPI/Swagger)
- ✅ Команды `make api-run`, `make api-test`, `make api-docs`

5. ✅ **Тестирование** - Unit и integration тесты компонентов
6. ✅ **Отладка и оптимизация** - Запуск, исправление багов

**Ожидаемые результаты:**
- ✅ Работающий dashboard с визуализацией статистики
- ✅ Dashboard доступен по пути `/dashbord`
- ✅ Интеграция с Mock API
- ✅ Покрытие тестами ключевых компонентов
- ✅ Документация компонентов

### FE-SP-4: Переход на Real API (✅ Завершено)

**Цель:**
Заменить Mock реализацию сборщика статистики на реальную, работающую с SQLite базой данных проекта. Обеспечить seamless переключение без изменений в frontend коде.

**Ключевые задачи:**
1. ✅ **Real StatCollector** - Реализация реального сборщика статистики из БД
2. ✅ **Интеграция с БД** - Подключение к SQLite через SQLAlchemy
3. ✅ **SQL запросы** - Разработка оптимизированных запросов для сбора статистики
4. ✅ **Переключение реализации** - Замена Mock на Real через конфигурацию
5. ✅ **Тестирование интеграции** - Проверка работы с реальными данными
6. ✅ **Оптимизация** - Индексы, кэширование, производительность

**Ожидаемые результаты:**
- ✅ Реализованный Real StatCollector (api/real_stat_collector.py)
- ✅ Интеграция с существующей SQLite базой (через SQLAlchemy async)
- ✅ Переключение Mock/Real через конфигурацию (.env: USE_MOCK_STAT_COLLECTOR)
- ✅ Оптимизированные SQL запросы (с использованием индексов)
- ✅ Тесты с реальными данными (17 тестов, 98.56% coverage)
- ✅ Документация API обновлена (README.md, EXAMPLES.md)

### FE-SP-5: Реализация ИИ-чата (✅ Завершено)

**Цель:**
Создать web-интерфейс чата для администратора с возможностью задавать вопросы о статистике диалогов на естественном языке. Система преобразует вопросы в SQL запросы, выполняет их и формирует ответ через LLM.

**Ключевые задачи:**
1. ✅ **UI чата** - Разработка интерфейса чата на основе референса
2. ✅ **Backend API для чата** - Создание API endpoint аналогичного боту
3. ✅ **Text-to-SQL функциональность** - Реализация преобразования вопроса в SQL через LLM
4. ✅ **Выполнение SQL** - Безопасное выполнение сгенерированных SQL запросов
5. ✅ **Формирование ответа** - Передача результатов SQL обратно в LLM для генерации ответа
6. ✅ **Интеграция и тестирование** - Полный цикл работы чата

**Ожидаемые результаты:**
- ✅ Работающий web-чат для администратора
- ✅ API endpoint для обработки запросов чата
- ✅ Text-to-SQL функциональность через LLM
- ✅ Безопасное выполнение SQL запросов
- ✅ Форматированные ответы на естественном языке

## Следующие шаги

После завершения frontend roadmap проект будет иметь:
- Полнофункциональный dashboard для мониторинга диалогов
- Web-чат для администратора с text-to-SQL возможностями
- Современный frontend с качественной кодовой базой
- Интеграцию frontend с backend через REST API

Каждый спринт будет планироваться детально в режиме Plan Mode. После выполнения спринта в таблицу будет добавлена ссылка на план реализации.

Новые спринты могут быть добавлены по мере развития проекта и появления новых требований.
